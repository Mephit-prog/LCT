## 4. Неопределённые входы, ordinal, пользователи

- **Q14–Q16, неопределённость.** Формула \(\text{variance}=1-\text{confidence}\) статистически не обоснована: у неё нет единиц, и confidence разных источников (OCR, справочник, LLM) не калиброван. Убираю её. До калибровки confidence работает только как порог для исключения или воздержания. Для калибровки нужна ручная разметка примерно 100–200 полей на тип поля и источник. Для числовых полей смотрим распределение ошибки, для категорий — изотоническую калибровку. Базовая линия: импутация плюс индикатор пропуска. Ядро на средних эмбеддингах для мягких категорий — приближение, а не интегрированный posterior. Полноценный вывод по скрытым входам откладываем.
- **Q25, идентифицируемость ordinal.** Предлагаю фиксировать шум probit равным единице, среднюю функцию нулевой, пороги свободными с приором. Пользовательские сдвиги порогов вводить только с сильным shrinkage, иначе стиль шкалы неотличим от вкуса. Отдельно: в моём `ordinal.py` \(\sigma_n\) из гауссовой подгонки не используется, а масштаб учитывается через амплитуду ядра. Вопрос о его законности открыт.
- **Q21, число параметров на пользователя.**

| Оценок | Что обучается |
|---|---|
| 0 | только общий prior |
| 1–4 | глобальные гиперпараметры фиксированы, обновляется только апостериор |
| 5–10 | плюс один масштаб пользователя |
| более 10–20 | плюс амплитуды по факторам с сильным сжатием к глобальным |

Персональный ARD по 15 параметрам при менее 10 оценках использовать нельзя.

- **Q30 и Q32, пользователи.** Единый \(\omega\) — заглушка, а не продуманная модель. Минимум: общие гиперпараметры по популяции, отдельный GP на пользователя. Мультипользовательский вариант подключаем только после EDA пересечения оценённых вин. Ещё одна ошибка: при `user=None` в `_cross` пользовательский множитель молча отключается. Нужны отдельные функции для известного пользователя, популяции и нового пользователя (там кросс‑ковариация с множителем \(\omega\)).
