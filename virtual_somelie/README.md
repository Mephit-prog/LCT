# virtual_somelie — исследовательский прототип

Математическая модель и offline-оценка, **не подключены** к HTTP/API или блоку сомелье в `web/`. Публичные средние оценки не являются персональными историями. Исходные решения: [план](MATHEMATICAL_IMPROVEMENT_PLAN.md) и [ответы](EXPERT_QUESTIONS.md).

## Запуск (Python 3.12)

```bash
python -m pip install -r requirements-somelie.txt
python -m pytest virtual_somelie -q
python -m virtual_somelie.diagnose --seeds 0 1 2 --n 300 --train 60 > ablation.json
python -m virtual_somelie.run_stage2 300 3 # исследование политики на синтетике
```

Запускать из `LCT/`. Для запуска на **собственных** данных отредактируйте `COLS` в `run_stage3.py` и проверьте: wine ID = (producer, cuvée, vintage), события содержат user, timestamp, явную оценку **после дегустации**; description/source доступен на момент рекомендации. Запустите `python -m virtual_somelie.run_stage3 wines.csv ratings.csv`. Результаты и manifests пишутся в текущую директорию (не в git). Каталог — фиксирован для temporal split; для new-wine split **до** оценки строить `build_table(wines, ..., fit_rows=training_wine_indices)` и использовать `make_manifest(..., protocol='new_wine', groups=cuvee_keys)` с глобально общими held-out cuvée. Ни покупки, ни просмотры не считаются отрицательным feedback.

## Что реализовано

- Фиксированная таблица (категории, полный региональный путь, числовая медианная импутация + маска, текст); при `fit_rows` vocab/marginal/median/scale не смотрят на test-вина. Непроверенная confidence только исключает поле, неправильный entity match — отдельный отказ. Для мягких категорий `P K Pᵀ` — **mean-embedding** физической смеси/приближение для неизвестного фиксированного атрибута, не полноценный posterior по скрытому входу. Matérn на импутированных данных — PSD; эвристика неоднородной pairwise variance удалена.
- Точный GP: по умолчанию аддитивное ядро, опции `additive_product`/`product` для ablation. Шум и веса с явным гауссовым prior **в log/logit координатах**, не Horseshoe; MAP не инвариантен к параметризации. При 1–4 оценках гиперпараметры фиксированы, 5–20 — только один персональный масштаб, >20 — MAP с сильным shrinkage; отдельный GP на пользователя. `fit_population_theta` обучает глобальные параметры **только на train событиях**, вызов — по решению исследователя после отдельного validation. Новый пользователь, известный пользователь и общая популяция имеют отдельные контракты (мультипользовательский вариант всё ещё исследовательский). Диагональ ядра корректна и для мягких признаков; неотрицательность posterior проверяется с допуском на численную ошибку.
- Gaussian baseline на звёздах и ordinal probit с фиксированным σ=1 и общей нулевой латентной средней, Laplace с line search и устойчивыми хвостами; `probability_at_least(J, level=4)` для ordinal выдачи. Ordinal threshold tuning — ограниченный приближённый evidence, Gaussian-prefit **приближение**, а не точная оптимизация совместных гиперпараметров.
- Offline ranking: temporal prefix/query, new-user, new-wine (группы cuvée), random **только для синтетики**; сохранение manifest + seed; test-оценки не влияют на popularity, shrinkage, kNN, Bayesian linear, GP. Метрики NDCG@5 с линейными gains, доля настоящих ≥4 в top-5, Spearman; парный bootstrap **по пользователям**. Эти метрики измерены только среди уже оценённых вин; без логов показов нет честной counterfactual оценки BO.
- Выдача батча без мутации обученной модели, криджинг-bеливер с фиксированными гиперпараметрами и шумом наблюдения, исключение показанных/оценённых, фильтры; EI против максимума posterior mean, Thompson с PSD-проверкой. `maxmin_init` может получать строки ядра без N×N матрицы.

## Gates и нерешённые вопросы

| Gate | Статус |
| --- | --- |
| G0: реальные персональные события и потолок шума | **не пройден**: подтверждённого датасета с историями/временем/признаками нет; шумовая надёжность не измерена |
| G1: математическая корректность | unit/regression/антиутечечные тесты проходят на текущем окружении; это не доказательство всех предположений и не заменяет independent validation |
| G2: выигрыш ≥0,02 NDCG@5 на ≥300 пользователях | **не проверен**; `paired_bootstrap` лишь рассчитывает gate при наличии данных, final test должен быть нетронутым |
| G3: выигрыш политики по итогам пилота | **не проверен**; симуляции ≠ пилот |
| G4: logging/exposure/latency/monitoring | **не начат** |

Отклонены: продуктово неподтверждённый чистый product-GP как default; confidence→variance; личная ARD на 5–10 оценках; объявление MAP prior «Horseshoe»; оценки тестовых пользователей в popularity; фиктивные оценки через мутирующий `.fit()`; универсальная рекомендация без user_id для ICM. Внедрение в продукт допускается после согласования feedback, consent/прав на источники, разметки entity-match и отдельного пилота с exposure и propensity. Предел шума и обратную связь разных пользователей на реальных данных ещё предстоит измерить; ограничения не маскируются синтетическими цифрами.
