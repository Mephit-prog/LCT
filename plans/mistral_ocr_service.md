# План: Mistral OCR в сервисе (рабочая ветка `lora-jina-synthetic_2`)

**Цель UX:** после установки зависимостей и однократного деплоя оператор задаёт только `MISTRAL_API_KEY` и запускает `python -m wineid.api`; тестовое фото через `POST /api/recognize` получает реальный OCR и ранжированный список кандидатов либо явный отказ. Это **не** обещание точного `slug` по одному ключу: калиброванная `WINE_POLICY`, проверенные данные, разрешение на передачу фото и лицензия модели — отдельные условия. Никаких ключей в git, браузере, логах или `.env.example` с реальным значением.

## Что уже есть / где искать

- `wineid/ocr.py`: `MistralOCR` делает POST `/v1/ocr` с `mistral-ocr-latest`, `image_url` как base64 data URI; парсит `pages[].markdown`, возвращает `OCRResult` со статусом и raw/normalized текстом. `MockOCR` — только fixture. **Реальный canary ещё не проведён**; совместимость с текущей схемой API не доказана.
- `wineid/roi.py` — ориентирование EXIF, проверка MIME/размеров, ROI; `wineid/pipeline.py` — ROI→OCR→`Index.search`→решение, общий deadline и семафор OCR. `wineid/api.py` — FastAPI `POST /api/recognize` (multipart `image`, необязательный `bbox`), `GET /api/health`, legacy `/v1/eval/predict`; `wineid/server.py` — альтернативный stdlib HTTP. `wineid/__main__.py offline --allow-live-ocr` — ручной пилот. Зависимости: `requirements-api.txt`.
- Сейчас `MISTRAL_API_KEY` уже подхватывается при запуске обоих серверов, **но** дефолт `WINE_ROI_MODE=refuse`: запрос без ручного bbox не вызывает OCR. Без `WINE_POLICY` ответ с кандидатами остаётся `ambiguous` и `slug=null`; `recognition_ready` проверяет OCR и ROI, но не качество и не калибровку. Нельзя представлять текущий сервер как готовый сервис «вставил ключ — получил точный SKU».
- `wineid/search.py` — уже существующий **лексический** blend внутри одного текстового индекса, `BLEND_VERSION=search-blend-v1`; это не объединение нескольких источников кандидатов. План межисточникового объединения: [candidate_source_blend.md](candidate_source_blend.md).

## Изменения по шагам

1. **Контракт и согласование:** выбрать и задокументировать дефолтный вход для фото без bbox (`center_80_crop` как ограниченный эвристический baseline либо `auto_bbox_experimental` только после проверки); сохранять ручной bbox как точный opt-in. Не делать молчаливый full-frame fallback при провале crop. Выбрать один путь HTTP (FastAPI), оставить совместимый stdlib без иной семантики. Утвердить разрешение на отправку ROI во внешний Mistral, лимиты расходов/данных и лицензию Jina перед включением CLIP.
2. **Provider canary:** по актуальной официальной документации Mistral проверить endpoint, имя модели/версионирование, допустимый image MIME/размер и data URI, ограничения, структуру `pages`, стоимость и retention. На разрешённом локальном ROI выполнить один opt-in платный вызов (никогда в CI), зафиксировать редактированный без PII результат и время; проверить пустые/многополосные `pages`. При расхождении обновить `wineid/ocr.py`, не подменять реальные ошибки mock-ответом. При необходимости дать явный `WINE_OCR_MODEL`, сохранив проверенный default.
3. **Key-only startup:** в `wineid/api.py:main` создать OCR только из непустого `MISTRAL_API_KEY`; в выбранной конфигурации включать согласованный безопасный ROI mode для запросов без bbox при наличии ключа (либо возвращать понятное требование bbox, если качество авто-ROI не подтверждено). Отсутствующий ключ → штатный `ocr_not_configured`, без скрытого MockOCR. Конфиг разрешает переопределить crop через `WINE_ROI_MODE`; `GET /api/health` честно отражает готовность именно OCR/ROI, отдельно от наличия policy/CLIP и производственной готовности. В `API.md` дать команды установки и запуска с единственным обязательным секретом и curl-пример, оговорить, что `slug=null` без калибровки — правильный ответ.
4. **Надёжность:** проверять оставшийся deadline перед кодированием/отправкой, выставить bounded connect/read/write timeout; 429/5xx, network, некорректный JSON, пустой OCR, отсутствие ключа должны давать различные безопасные статусы. Нынешний синхронный `httpx.Client` может выйти за общий wall-clock deadline (в том числе DNS/подвисший socket): добавить принудительный ограничитель на уровне запроса/изоляции worker и проверить, что при таймауте нет бесконтрольных фоновых вызовов/утечки слотов; не вводить бесконечных retries. Ограничить конкуренцию OCR и размер фото, не логировать текст, фото, URI или Authorization.
5. **Тесты без денег и smoke:** mock HTTP transport для реального JSON `pages[].markdown`, пустого текста, malformed, 429, 5xx, timeout, MIME, Unicode, ключа и отсутствия секретов; API-тест от multipart через ROI до `candidates`, а также старт без ключа/с ключом. Отдельный opt-in canary только при явном разрешении. На независимых размеченных фото сравнить ручной ROI/авто-ROI, OCR против ручного текста по Recall@K, unknown и похожие SKU, p50/p95 и расходы; без этого не калибровать `WINE_POLICY` и не обещать acceptance.

**Приёмка этапа интеграции:** свежий запуск после установки `requirements-api.txt` и передачи одного ключа действительно обращается к Mistral на запросе без bbox (если согласован auto-ROI), отдаёт raw OCR + кандидатов/понятный отказ; без ключа ничего не отправляет; тесты не платят провайдеру. Для принятия точного slug нужны отдельные B01/B02/B08–B10 из [STATUS.md](STATUS.md).
