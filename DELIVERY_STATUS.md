# Статус поставки

Исходный код бэкенда один: `wineid/`. Инструкция запуска: [RUN_GUIDE.md](RUN_GUIDE.md).
На Windows с Python и Node.js 18+ выполните перед передачей комплекта:

```powershell
python build_windows_bundle.py D:\LCT --provision
```

Команда собирает `D:\LCT\backend` (веса копируются из `artifacts/`), `web`, `local`, устанавливает backend `.venv` и `web/node_modules` без второй поддерживаемой копии кода. Сборщик загружает pinned HF-веса/code в `backend/artifacts/hf-cache` и проверяет повторную загрузку offline; для этого нужны сеть, достаточно RAM и согласованная лицензия. **Windows-сборка и запуск пока не подтверждены на целевой машине.** Фронтенд переведён на Vite 5; `npm ci` и тесты проверены на Node.js 18.20.8.

MinerU cloud обрабатывает изображения при `WINE_OCR_PROVIDER=mineru` и `MINERU_TOKEN`; `mineru_local` — прежний локальный CLI. Cloud OCR не разрешает policy accepted. Токен задаётся через окружение; ранее опубликованный ключ удалён из инструкции, но остаётся в истории Git и требует отзыва у провайдера. Квота и срок нового ключа требуют согласования с организаторами.

Остаются до готовности: реальный Windows smoke (CLIP + MinerU, валидный конкурсный ключ и целевые веса), измерения p50/p95, перегрузка и независимый validation/test качества. Интеграционный облачный smoke нельзя безопасно выполнять в CI без разрешения и квоты. Текущий frontend скрывает отправку заявки и сомелье, пока backend не реализует эти операции.

- Backend в текущем окружении: 259 passed, 6 skipped, 1 failed из-за отсутствующего `pypdf` (объявлен в `requirements-mineru.txt`). Полный зелёный прогон требует установки dev-профиля; облачные/model smoke не запускались.
- Pyflakes, compileall, `git diff --check` и регрессия сборщика комплекта прошли.
- Frontend: `npm ci`, 78 passed / 7 skipped, type-check и production build прошли.
- `npm audit`: 4 уязвимости — `vitest` critical, `vite` high, `vite-node` и `esbuild` moderate. Обновление toolchain и проверка совместимости остаются отдельным блокером security-ревью; автоматический `audit fix --force` не применялся.
- Исторические материалы перенесены в игнорируемую `.temp/`; архив существует только на рабочей машине. Отличающиеся agent worktrees сохранены там без объединения с основным кодом.
