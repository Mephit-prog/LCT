# ТЗ: пайплайн данных и обучения для распознавания этикеток вин

## 1. Назначение

Система сопоставляет русскоязычное описание вина и фотографию бутылки или этикетки. Рабочий режим — поиск по индексу, а не классификатор с фиксированным числом классов. Новая SKU добавляется карточкой и кадром, без полного переобучения.

Дообучение CLIP допустимо только как второй этап, после нулевого индекса и только если на отложенных хозяйствах растёт Recall@1.

## 2. Объекты данных

### 2.1. Каталог вин

Файл `wines.csv`. Одна строка — одна SKU.

| Поле | Обязательность | Правило |
|---|---|---|
| `wine_id` | да | Стабильный идентификатор, не название файла |
| `name_ru` | да | Каноническое русское имя без маркетингового хвоста |
| `producer` | да | Канонический производитель |
| `color` | нет | Красное, белое, розовое или пусто |
| `vintage` | нет | Четыре цифры `19xx` или `20xx`, иначе пусто |
| `ean` | нет | Штрихкод, если есть |
| `producer_split` | да | `train`, `val` или `test`; одно значение на все вина хозяйства |

Разные годы одного имени — разные `wine_id`. Не сливать.

### 2.2. Изображения

Файл `images.csv`. Одна строка — один файл.

| Поле | Обязательность | Правило |
|---|---|---|
| `image_id` | да | Стабильный идентификатор |
| `wine_id` | да | Ссылка на каталог |
| `path` | да | Относительный путь к файлу |
| `view` | да | `studio_front`, `field_front`, `field_angle`, `shelf`, `user`, `external` |
| `sha256` | да | Хеш байтов файла |
| `source` | да | `own`, `strapi`, `portal_user`, `winery`, `roskachestvo`, `other` |
| `source_url` | нет | Откуда взят внешний файл |
| `ocr_hit` | да | `name`, `producer`, `both`, `none` |
| `usable_train` | да | `0` или `1` после фильтров раздела 4 |

### 2.3. Канонический текст

Один шаблон на все вина и все эпохи:

```text
Фотография бутылки вина «{name_ru}», производитель {producer}, {color}, {vintage}
```

Пустые хвосты отрезаются. Если нет цвета и года, строка заканчивается на производителе. Шаблон между экспериментами не менять. Аугментации текста в обучении нет.

Алиасы производителя (`Fanagoria` / `Фанагория`) хранить отдельной таблицей. Автоматическую транслитерацию не использовать.

## 3. Внешние данные

Внешний кадр попадает в train только после привязки к существующему `wine_id`. Файл без SKU класс не создаёт.

Порядок для сайта винодельни, Роскачества, карточки магазина и пользовательского фото:

1. Свести запись к `source`, `source_url`, `raw_name`, `producer`, `vintage`, `image_url`.
2. Нормализовать текст: `ё` → `е`, снять кавычки, регистр и двойные пробелы. Удалить служебные слова `вино`, `столовое`, `сухое`, `полусладкое`, `згу`, `знпм` и объём `0.75`.
3. Привязать точным совпадением нормализованных имени и производителя. Год, если есть в обоих местах, тоже должен совпасть. Fuzzy-сопоставление допустимо только при уже совпавшем производителе и малом расстоянии по имени. Сомнительное — в ручную проверку или в отвал, не в автоматический класс.
4. Скачать байты, посчитать `sha256`. Повторный хеш не хранить второй копией.
5. Прогнать фильтры раздела 4. Прошедшее записать с `view=external`.

Доля `external` в обучающем батче — не больше 30%. Остальное — свои полевые, пользовательские и студийные кадры.

WineSensed и прочие чужие каталоги не добавлять «для объёма». Кадр используется только если нормализованное имя совпало с карточкой своего каталога. Несовпавшее отбрасывается.

В репозиторий попадают только файлы, право на хранение и распространение которых есть. Источник и лицензия остаются в `images.csv`.

## 4. Чистка и отбор

### 4.1. Отвал

Файл не используется ни в train, ни в галерее метрики, если выполняется хотя бы одно условие:

- короткая сторона меньше 256 px или размер меньше 15 КБ;
- это не фото этикетки: заглушка, логотип, коллаж «бутылка + бокал + акция»;
- на кадре две или больше бутылок;
- один и тот же `sha256` связан с разными `wine_id` — снять обе связи;
- near-duplicate: pHash-расстояние меньше 6 между кадрами разных вин — снять обе связи, «лучшую» не выбирать;
- `ocr_hit=none` для `external` и `user`;
- чужой водяной знак занимает существенную часть кадра, либо этикетки не видно.

Блик, наклон и полка не являются причиной отвала.

Студийный кадр с мелким шрифтом и `ocr_hit=none` можно оставить один на вино, только если привязка к карточке подтверждена человеком. В contrastive train его не класть, если нет второго годного кадра.

### 4.2. Лимиты на вино

- не больше 1 кадра `studio_front` или `external`;
- не больше 8 кадров `field_*`, `shelf` и `user` суммарно;
- вино без годного файла в галерею не входит;
- вино с одним кадром в contrastive train не входит: его можно держать только в индексе.

`usable_train=1` ставится только если у вина есть хотя бы два разных годных кадра и хотя бы один из них не студийный packshot.

### 4.3. Сплит

Резать по производителю, не по файлам одной бутылки. Все вина одного `producer` имеют один `producer_split`.

- `train` — 80% хозяйств;
- `val` — 10%;
- `test` — 10%.

В train оставлять хозяйства, у которых есть хотя бы одно вино с парой «студия или external + полевой или user». Хозяйства без полевых кадров не использовать как единственную опору качества.

## 5. Нулевой индекс

До любого fine-tune считается baseline.

- Энкодер: мультиязычный CLIP с рабочей русской текстовой башней. Для некоммерческого baseline допустим `jinaai/jina-clip-v2`. Для весов, которые должны свободно использоваться дальше, брать модель с лицензией, разрешающей такое использование.
- В индекс пишется L2-нормированный вектор канонического текста каждой SKU и вектор каждого годного фото.
- Запрос текстом ищет по фотогалерее. Запрос фото ищет по текстам карточек.

Этот прогон обязателен. Fine-tune без него не принимается.

## 6. Обучение

Запускать только если нулевой Recall@1 на val проседает на хозяйствах с похожими этикетками и в train есть не меньше примерно 300 разных этикеток с полевыми кадрами. Иначе оставить индекс.

### 6.1. Что учить

- Текстовую башню заморозить.
- В vision разморозить последние 2–4 блока и проекцию.
- Loss — симметричный InfoNCE.
- Температура 0.02–0.07, обучаемая.
- Оптимизатор AdamW, weight decay `0.01`, warmup 5% шагов.
- Learning rate `1e-5` на размороженных блоках и `1e-4` на проекции.
- 3–10 эпох, ранняя остановка по Recall@1 на val, не по loss.

Позитив — кадр и канонический текст его `wine_id`. Студия и external вместе не больше половины батча. Негативы внутри батча: 50% другие вина того же производителя, 50% случайные из train. Размер батча 64–128. Разрешение — по карточке модели; для `jina-clip-v2` это 512.

Аугментации только изображения: crop 0.8–1.0, поворот ±8°, яркость, JPEG, лёгкий блик.

### 6.2. Остановка

Если после трёх эпох Recall@1 на val не выше нулевого индекса, обучение прекратить и в выдачу отдать нулевые веса.

## 7. Приёмка

Считать на `test`, галерея — одно случайное годное фото на вино.

| Протокол | Запрос | Галерея |
|---|---|---|
| T2I | канонический текст | фото |
| I2T | полевое или user-фото | тексты карточек |
| hard | тот же T2I | только вина того же производителя |

Метрики: Recall@1 и Recall@5. Отдельно Recall@1 на `field`/`user` и на `external`.

Падение полевого Recall@1 при росте внешнего означает, что доля `external` в батче слишком велика. Долю уменьшить и прогон повторить.

В отчёт кладутся оба прогона: нулевой индекс и лучший чекпоинт. Чекпоинт без таблицы сравнения не считается результатом.

## 8. Выдача

В рабочий контур кладётся индекс, не softmax по классам.

1. Вектор канонического текста каждой SKU.
2. Вектор каждого годного фото этой SKU.
3. Поиск top-20 по текстовому или визуальному запросу.
4. Внутри top-20 поднять кандидатов, у которых OCR содержит `name_ru` или `producer`.

Новое вино добавляется строкой в `wines.csv`, файлом в `images.csv` и новыми векторами. Полное дообучение повторять только после накопления ещё нескольких сотен полевых кадров, если hard Recall@1 снова упирается в похожие этикетки одного хозяйства.
