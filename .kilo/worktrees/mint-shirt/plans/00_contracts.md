# Общие контракты и правила

## Источники и идентичность

Не менять исходные CSV, uploads, архивы и `eval/`. Читать изображения по содержимому, поддерживать Unicode-пути и EXIF. `wine_id` в MVP соответствует точному уникальному `Slug`; возвращаемый `slug` — исходная строка CSV. Разные урожаи/slug не объединять по похожему названию или изображению. `query_id` обозначает фото, `roi_id` — его crop; при нескольких бутылках без выбора возвращать `ambiguous_scene`, а не смешивать их текст. `asset_id` — хеш содержимого файла; suffix Strapi и имя файла не подтверждают принадлежность вина.

## Минимальный обмен для MVP

Формат может быть JSONL/Parquet или типизированными Python-структурами: не создавать отдельный файл для каждого этапа онлайн-запроса. Важна семантика полей и сохранение диагностик для offline-оценки.

| Сущность | Минимальные поля |
|---|---|
| Каталог | `wine_id`, `slug`, исходные и нормализованные название/производитель, описание/категория при наличии, `source_row_ids`, версия CSV |
| Проверенная gallery | `wine_id`, `asset_id`, путь, `roi_id`, роль этикетки (если известна), `mapping_status=verified`, источник и метод ручной проверки; неподтверждённые ссылки отдельно |
| ROI | `query_id` или `asset_id`, `roi_id`, путь/байты crop, `status=manual|segmented|fallback_bbox|unusable`, размер ориентированного источника, bbox `[x0,y0,x1,y1)` в его координатах, версия crop |
| OCR | `roi_id`, `status=ok|no_text|timeout|provider_error|invalid_input`, raw text, нормализованный текст, модель/версия, latency; несуществующие у провайдера boxes/confidence — `null` |
| Кандидаты | `query_id`, список уникальных `wine_id` со score, rank, объясняющим совпадением и явным расстоянием Левенштейна; `no_text` — пустой список |
| Решение | `query_id`, `status=accepted|ambiguous|unknown|unreadable|ambiguous_scene|error`, `slug` только при accept, reason codes, версии, тайминги; score не называть вероятностью без калибровки |

Для каждого offline-запуска хранить конфигурацию/хеш входа/версии используемых моделей; для работающего сервиса — совместимую версию каталога и gallery. Не смешивать embeddings разных моделей или preprocessing. Расширенные поля (маски и transform, сущности OCR, feature observations, calibrator, подробные scores) добавлять **когда появляются соответствующие потребители**, а не требовать от baseline. Неизвестные значения — `null`, не 0; не сериализовать NaN/Infinity.

## API

`POST /v1/recognize`, multipart `image` → статус, `slug` или `null`, reason codes. `POST /v1/eval/predict` → только `{"slug":"точный-slug"}` или `{"slug":null}`. Проверить реальное поведение `eval/participant_test.sh`: при отказе он записывает null, а не считает это правильным ответом. Не подставлять произвольный slug ради непустой строки.

## Данные и оценка

- Сначала дедупликация кадров/производных, затем split по исходной съёмке/near-duplicate группе. Query test не совпадает с gallery кадром или его производной; независимое фото того же вина в gallery допустимо.
- Для open-set нужны query вин вне каталога и не-винные объекты. Точный slug подтверждается независимой разметкой; объективно неразличимые SKU помечаются ambiguous.
- `eval/` без GT служит только проверке совместимости и финальному запуску, не настройке crop, подсказок, порогов или таблицы hash→slug.
- Фикстуры и ручные ROI позволяют разрабатывать этапы параллельно, но не являются доказательством качества на реальных фото.

## Безопасность

Лимиты bytes/pixels/времени декодирования и числа ROI; MIME по содержимому. В OCR передавать только разрешённый crop, ключи держать в secrets, не логировать изображения/полный текст по умолчанию. OCR-текст — недоверенный ввод. Проверить лицензии выбранных весов, SDK и fuzzy-backend до production. Один общий monotonic deadline ограничивает все сетевые попытки; `eval` ждёт не более 10 с.
