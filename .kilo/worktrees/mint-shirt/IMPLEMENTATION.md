## Online behavior and refusal

By default the endpoint **validates but refuses the unlocalized photo** (`unreadable`, reason `automatic_roi_unavailable`) and returns `{"slug":null}` on the eval endpoint. This is intentional: there is no trained/validated automatic label locator and a whole image cannot be represented as a found ROI. For an explicitly *experimental full-frame ablation* set `WINE_ROI_MODE=full_frame_experimental` before starting the server. This runs OCR on the whole oriented image, marks `fallback_bbox` and `full_frame_experimental`, **does not solve multi-bottle detection**, and must not be reported as automatic localization. Alternatively install `requirements-vision.txt` and set `WINE_ROI_MODE=auto_bbox_experimental`: a conservative high-contrast rectangular contour proposes one bbox, crops from the oriented original, and refuses when no candidate (`unreadable/no_label_bbox`) or multiple separate candidates (`ambiguous_scene/multiple_label_bboxes`) are found. It is **not validated on real wine photos**; a single rectangle may be something other than a label. Before enabling it for real images, compare it against full-frame and manual ROI on independent validation: usable ROI, preserved name/year, OCR recall, refusals, latency. Do not tune using `eval/`. Offline `wineid.compare` checks paired hashes, ground truth, source groups, splits and search/policy/catalog versions, and flags mock transcriptions; paired results using mock text measure localization coverage only, not OCR benefit. `/ready` reports whether OCR and policy are configured; catalog readiness does not imply recognition readiness. No cross-request image/OCR logging; the intended server budget is 8.5s including request-body read, with no OCR retries. This is not a hard wall-clock guarantee: socket/HTTPX timeouts bound individual waits, and post-call deadline checks do not interrupt ongoing work. Slow-body/provider tests and a bounded worker/resource design remain required. At most two OCR calls run concurrently per process; excess requests return `error/ocr_capacity_exceeded` rather than queueing behind the deadline. This does not bound the number of HTTP connections or replace a production reverse proxy.

The policy is **absent by default**: matches are candidates, never probabilities; manual-text pipeline abstains `ambiguous` until independently calibrated. Once validation with unknowns and similar vintages supports it, pass `WINE_POLICY=/absolute/path/policy.json` containing e.g. `{"min_score":95,"min_margin":8,"max_distance":0.05,"version":"validation-2025-01"}`. **These example numbers are not calibrated recommendations.** Check version, exact-slug errors and unknown false-accepts on untouched test before deployment. OCR is invoked only for manually selected offline ROI or explicitly enabled experimental automatic/full-frame crop. Secrets in environment (`MISTRAL_API_KEY`), not JSON; production requires approval of external crop transmission and validation of the API's current data retention, pricing, model, and response schema. Model default is `mistral-ocr-latest`; CI uses mocks, and **no real canary has been run**. Verify current provider documentation before a paid canary. Truncation/error/timeout produce null, not a made-up slug. HTTPS and authentication should be added before exposing externally; server binds 127.0.0.1 by default.

After service is ready: `cd eval && shasum -a 256 -c checksums.sha256` (or equivalent) then run `bash eval/participant_test.sh --images-dir eval/queries --manifest eval/queries.tsv --endpoint http://127.0.0.1:8080/v1/eval/predict --output artifacts/predictions.jsonl` from repo root. This tests **format only**, not accuracy.

## Offline CLIP experiment (plan 05)

`python3 -m pip install -r requirements-clip.txt` installs optional CLIP dependencies. The image-to-image backend is now **Jina CLIP v2**, with explicit `--allow-remote-code` approval after HF code and CC BY-NC 4.0 license review (tests inject deterministic embeddings; no weights downloaded). The frozen model is loaded once and applied with the same Jina RGB preprocessing to manually cropped reference and query ROI. `--revision` (legacy alias `--pretrained`) is now a full HF weights commit SHA. Old OpenCLIP galleries/policies must be rebuilt/recalibrated. Neither server nor `Pipeline` uses CLIP for live decisions. This legacy experiment is not the OCR-free zero-shot path described in [JINA_CLIP.md](JINA_CLIP.md).

```bash
python3 -m wineid audit artifacts/gallery.jsonl artifacts/queries.jsonl  # resolve all errors first
python3 -m wineid.clip_eval build artifacts/gallery.jsonl artifacts/gallery.npz --allow-remote-code
python3 -m wineid offline artifacts/queries.jsonl artifacts/text.jsonl # manual_text oracle, or --allow-live-ocr with consent
python3 -m wineid.clip_eval evaluate artifacts/gallery.npz artifacts/queries.jsonl artifacts/text.jsonl artifacts/clip.jsonl --split validation --mode fusion --weight 0.5 --allow-remote-code
# Independent untouched test, only after freezing configuration and policy:
python3 -m wineid.clip_eval evaluate artifacts/gallery.npz artifacts/queries.jsonl artifacts/text.jsonl artifacts/test-clip.jsonl --split test --mode fusion --weight 0.5 --policy artifacts/visual-policy.json --calibration-manifest artifacts/calibration.jsonl --allow-remote-code
```

`--mode clip` evaluates pure cosine reranking; `--role front|back|neck` restricts references to the chosen role. Full text Top-K reference coverage is required for reranking; otherwise `missing_reference` abstains. Output includes per-candidate cosine, best reference/count, original text and CLIP/fusion order, versions and timings; the printed paired report includes GT-in-K conditional and unconditional retrieval Top-1, helped/harmed IDs, decision metrics and unknown false accepts. Manual text is an **oracle**, not OCR evidence. Cosines/fused scores are **not probabilities**; `confidence_calibrated` stays null. Decisions abstain without an independently validated `visual-policy-v1` artifact matching `wineid.clip_eval.VisualPolicy`, including exact model/gallery/config fingerprints, calibration manifest hash/source groups and artifact checksum. No default thresholds are supplied. Freeze role, weight, policy and model using validation before untouched test. Unknown/open-set errors and adjacent vintages must be evaluated; adding CLIP to HTTP needs measured improvement, a verified gallery and a shared-deadline budget. No quality claims follow from the fixture tests.

## Заметки: выделение ROI этикетки при помощи CLIP (offline-прототип; не валидирован)

**Что есть в коде (обновлено для Jina).** `wineid.visual.CLIPEmbedder` загружает frozen Hugging Face `jinaai/jina-clip-v2` и в `torch.inference_mode()` считает **глобальный embedding уже вырезанного** RGB crop; `build_gallery` строит эмбеддинги из `manual_roi`, `Gallery.scores` сравнивает их по cosine, `wineid.clip_eval.evaluate` берёт query ROI из `bbox` манифеста. Ни один из этих шагов не возвращает положение этикетки на исходном фото. `wineid.roi.auto_bbox_roi` — контуры OpenCV, без CLIP; онлайн `Pipeline` по умолчанию отказывается от автоматической локализации. Нельзя называть CLIP-rerank выделением ROI или считать cosine координатой/уверенностью локализации.

**План дальнейшей проверки offline-прототипа** (см. `plans/additional_label_segmentation.md`):

1. Подготовить размеченные вручную bbox/маски этикеток на независимых фото, разделить по `source_group` до настройки; отдельно проверить маленькие надписи, блики, разные роли и несколько бутылок. `eval/` не использовать. В качестве баз сравнить `manual_roi`, `auto_bbox_roi` и `full_frame_roi`; без измерений не подключать эксперимент к серверу.
2. Зафиксировать локализующий checkpoint (план предлагает ViT-B/16, **не** автоматически совместимый с текущей gallery Jina), лицензию, preprocessing и неизменные prompts вроде «wine bottle label» против фона. Посчитать text embeddings один раз. Для полного ориентированного изображения (`roi.decode`: EXIF, MIME/лимиты) сделать forward с доступными градиентами по целевому image–text similarity; получить пространственную CAM по patch tokens подходящего слоя, предварительно проверив ненулевой gradient. Текущий `CLIPEmbedder.__call__` в `inference_mode()` для CAM не годится: нужен отдельный интерфейс/проход, проверка корректности hooks и освобождения памяти. Проверить на ручной разметке, что карта покрывает **всю этикетку**, а не только логотип/одну строку; GradCAM здесь гипотеза, не готовый детектор.
3. Сохранить геометрию преобразования CLIP (resize, crop, смещения): стандартный `open_clip` preprocess может делать center crop, теряя края. При переносе CAM в координаты **ориентированного оригинала** не выдумывать значения за пределами видимого CLIP участка. Возможен tile/multiscale прогон, но его стоимость и правила объединения измерять отдельно. Нулевая/плоская карта и малая видимая область → отказ, не «уверенный» bbox после нормализации.
4. По CAM получить ограниченный bbox с запасом для названия и года; GrabCut на уменьшенной копии — только отдельная проверяемая абляция для уточнения границы. Цветной немаскированный crop брать из оригинального разрешения через общий `_bbox_crop`/ROI-контракт (`roi_id`, `source_sha256`, `source_size`, half-open `bbox`, `crop_version`, `status`). Надёжный bbox при плохой маске → `fallback_bbox`; нет пригодной локализации → `unusable`/отказ, **не** полный или центральный кадр под видом найденной этикетки. Если несколько независимых правдоподобных бутылок без выбора — `ambiguous_scene`; не смешивать этикетки.
5. После пилота добавить отдельный opt-in backend ROI в `Pipeline` только при выигрыше на независимой validation по usable ROI, сохранности названия/года, OCR→Recall@K, отказам, p50/p95 и памяти в общем deadline. Ограничить число проходов/ROI и конкуренцию; query embedding для существующего image-to-image rerank требует отдельного прохода по вырезанному crop. При изменении checkpoint или crop/preprocessing **пересобрать gallery** (`wineid.visual.CROP_VERSION`/metadata) и повторить парную проверку `clip_eval`; не смешивать эмбеддинги разных версий. На неизменённом test измерить ошибки, включая unknown и соседние урожаи. Пока таких данных/тестов нет, это план, не реализованная возможность и не гарантия качества.

### Реализован offline-прототип CLIP CAM и проверка

`wineid/clip_roi.py` — **отдельный эксперимент**, не серверный ROI backend. `CLIPCAM` строит Grad-CAM по предпоследнему блоку OpenCLIP ViT-B/16 и фиксированной разности двух text prompts; квадратный белый letterbox не обрезает края через center crop. `cam_bbox` преобразует карту patch-токенов обратно в ориентированные координаты, отказывается от пустой карты и нескольких областей; `clip_cam_roi` возвращает цветной crop оригинала со статусом `fallback_bbox`. Карта **не является маской этикетки или confidence**, а расширение на один patch может захватывать фон. GrabCut не реализован. `Pipeline`/HTTP не используют CAM; локализатор OpenCLIP ViT-B/16 не подменяет энкодер Jina текущей image-to-image gallery. CAM hooks на Jina не переносились.

```bash
# Сначала python3 -m wineid audit ... на независимых размеченных gallery/query.
# После проверки лицензии и явного разрешения скачивания весов:
python3 -m pip install -r requirements-clip.txt -r requirements-vision.txt
python3 -m wineid.clip_roi artifacts/queries.jsonl artifacts/cam-validation.jsonl --split validation --allow-checkpoint-download
# Порог и prompts зафиксировать до запуска на test; затем отдельная оценка OCR.
```

`clip_roi` выводит bbox, IoU, долю сохранённой GT-области, отказы, p50/p95; не измеряет сохранность надписей, OCR, память или точность распознавания. Результаты сравнивать с ручными ROI и OpenCV bbox на **том же** независимом validation, с раздельным `source_group`; это не включено в автоматический запуск. Тесты с внедрёнными фиктивными CAM (без весов и загрузки моделей): `python3 -m pytest -q` — **22 passed**. Дополнительная проверка на 3 синтетических однотипных прямоугольниках с фиктивной CAM: локализовано 2/3, IoU≥0.5 — 0/3, покрытие GT≥0.9 — 2/3; OpenCV нашёл обе рамки и отказал на пустой сцене. Это тест геометрии/отказов, **не измерение качества CLIP**, и даже здесь чрезмерно широкий CAM bbox хуже OpenCV по IoU. На момент запуска отсутствуют `open_clip`, утверждённые веса и независимые размеченные реальные query; поэтому **реального прогона Grad-CAM, сравнения OCR и проверки на test не было**. Не интерпретировать фикстуры или фотографии `eval/` как валидацию. Для настоящей проверки нужны разрешение на checkpoint, разметка и отдельно зафиксированные пороги/промпты на validation.

## Реализация ТЗ tz-clip-text-ranking.md / tz-wine-label-retrieval.md

Начата реализация по двум новым ТЗ (см. корневые файлы). Код идёт **без изменения контрактов** существующих тестов (`python3 -m pytest -q` — **65 passed**); веса/OCR не скачивались, обучение не запускалось.

- **`wineid/canonical.py`** — нормализация по ТЗ (NFKC, casefold, `ё→е`, снятие кавычек, схлопывание пробелов), `extract_vintage` (19xx/20xx), `name_tokens` (служебные токены `вино/сухое/полусладкое/згу/знпм` и объёмы не считаются именем), `token_f1`, один канонический шаблон `Фотография бутылки вина «{name_ru}», производитель {producer}, {color}, {vintage}` с обрезкой пустых хвостов, таблица алиасов производителей.
- **`wineid/catalog.py`** — `structured_fields()`/`structured_wine()`: `name_ru`, `producer`, `color` (из Категории, 4 стабильных значения), `vintage` (из названия, не из slug), `grape`, `sweetness`. Конструктор `Wine` не менялся.
- **`wineid/search.py`** — переработанное текстовое ранжирование по ТЗ §4.1: IDF-взвешенное токенное доказательство (редкие токены, напр. сорт «Сибирьковый», разрывают tie семей с одинаковыми названиями) + fuzzy только для расширения пула при опечатках (с токенным префикс-пред-фильтром, review P2-18); `score = s_retrieval + 0.15·token_f1 + 0.10·prod_hit` (s_retrieval — офлайн-прокси `0.5·(1−dist)·100 + 0.5·evidence_norm`, веса-заглушки до калибровки на val); `vintage_mode=soft|hard`; `equivalence_groups()`/`collision_stats()` — неразличимые по каноническому тексту группы (по текущему CSV: 55 групп / 116 SKU, 5,5%). Fuzzy-бэкенд: `fuzzywuzzy` (GPL-2.0) — единственный production-бэкенд, оставлен решением (review P1-6); при отсутствии активируется не-score-совместимый difflib-fallback для офлайн-тестов с явным предупреждением. Измеренные улучшения: «Арпачино Иноходец Сибирьковый» больше не tie (верный SKU первый, отрыв ~15 баллов); «Пино Нуар» остаётся tie → `ambiguous` без принудительного Top-1; «4 elements Рислинг сухое/полусухое» — tie пары (по ТЗ неразличимы лексически), посторонние SKU отсеяны.
- **`wineid/catalog_export.py`** — генерация `wines.csv` (wine_id, name_ru, producer, color, vintage, ean, producer_split 80/10/10 по хэшу производителя) и `images.csv` (image_id, wine_id, path, view=studio_front, sha256, source=strapi, ocr_hit=none, usable_train=0) из CSV+uploads через кандидатные связи `catalog_media` с фильтрами ТЗ §4.1 (размер ≥15 КБ, короткая сторона ≥256 px, лимит MAX_BYTES, sha256 не делится между wine_id). Контракт пути (review P1-2): колонка `path` относительна корня `uploads` (`--uploads`); обучение резолвит её через `--images-root <тот же корень>`. Реальный прогон: 2103 wine-строки, 1375 image-строк из 1699 кандидатов (404 unresolved, 41 shared-sha256, 216 small-side, 64 too-small, 3 undecodable; без pHash-фильтра). pHash-дедупликация реализована (`wineid/phash.py`, Hamming < 6 между разными `wine_id` снимает обе связи); multi-bottle и водяные знаки **не** реализованы — требуют внешней разметки.
